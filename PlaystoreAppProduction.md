# Google Play Store Production Checklist — Thero Idle TD

Status of the project today: a **browser-first static HTML/JS/TS game** (`index.html`
+ `assets/` + `scripts/`, built to `dist/` via `npm run build`), with an Electron
wrapper (`electron/main.cjs`) used only for local desktop testing. There is
currently **no Android project of any kind** in this repository. Everything below
is what has to be created or changed to ship on Google Play.

---

## 1. Pick a packaging approach

The game is a web app, so there are three realistic paths:

| Option | What it is | Trade-offs |
| --- | --- | --- |
| **Capacitor** (recommended) | Wraps `dist/` in a native Android WebView shell; gives real native plugin access (billing, haptics, filesystem, splash screen) | Extra native project to maintain; ~5 MB overhead; full Play feature access |
| **TWA / Bubblewrap** | Trusted Web Activity pointing at the hosted GitHub Pages build | Requires the game to be a fully valid PWA served over HTTPS; needs Digital Asset Links; no offline play unless a service worker caches everything; harder to do IAP |
| **Cordova** | Older equivalent of Capacitor | Legacy; only choose it if a required plugin exists nowhere else |

Recommendation: **Capacitor**. It keeps the existing `dist/` pipeline as the
single source of truth (`npm run build` → `npx cap sync`) and does not require
the game to be internet-reachable at runtime.

Work item: add `android/` (generated by `npx cap add android`), add `capacitor.config.ts`
pointing `webDir` at `dist`, and add npm scripts like `android:sync` / `android:open`.

---

## 2. Make the build fully offline-capable

Play users expect the game to launch without a network. Today `index.html` loads
two hard dependencies from the public internet:

- `index.html:10` — Google Fonts CSS (`Cormorant Garamond`, `Great Vibes`, `Space Mono`)
- `index.html:33` — MathJax 3 from `cdn.jsdelivr.net`

Both must be **vendored locally** before shipping:

- Download the WOFF2 font files into `assets/fonts/` and replace the Google Fonts
  `<link>` with local `@font-face` rules. Confirm the licenses (all three are SIL
  OFL) and ship the license text in the app's credits/legal screen.
- Vendor the MathJax `tex-mml-chtml.js` bundle (plus its `output/chtml/fonts/`
  directory) into `assets/vendor/mathjax/` and point the `<script>` at the local copy.
  MathJax is Apache-2.0 — include the notice.
- Re-check `electron/main.cjs` CSP afterward: the `https://cdn.jsdelivr.net`,
  `https://fonts.googleapis.com`, and `https://fonts.gstatic.com` entries should be
  removable once everything is local. The Android WebView should ship with the same
  tightened CSP.

Also audit for any other absolute `http(s)://` asset references before release.

---

## 3. Mobile input, layout, and lifecycle

`docs/PLATFORM_SUPPORT.md` states the game is mobile-first, but that has to be
verified on real hardware, not just a narrow browser window:

- **Touch**: confirm every interaction (tower placement, drag, upgrade panels,
  wave editor, codex/field-notes overlays) works with touch events, not just
  mouse events. Verify no `:hover`-only affordances.
- **Safe areas**: honor `env(safe-area-inset-*)` for notches and gesture bars.
- **Orientation**: decide portrait-only vs. both, and lock it in the Android
  manifest to match what the UI actually supports.
- **Back button**: Android's system back must do something sensible (close the
  top overlay, then prompt to exit) — otherwise it kills the app mid-run.
- **Suspend/resume**: the idle loop must handle the app being backgrounded.
  Verify offline-progress math against wall-clock time, not frame counts, and
  test that pausing/resuming does not double-award or stall production.
- **Performance**: profile on a low-end device (a 3–4 year old midrange phone).
  Target a stable 60 fps in mid/late waves; check `docs/PERFORMANCE_OPTIMIZATION_PROGRESS.md`
  for known hot spots.
- **Audio**: mobile browsers/WebViews block audio until a user gesture. Confirm
  `assets/audioSystem.js` initializes on first tap and respects the device
  silent switch / media volume.

---

## 4. Save data durability

The game saves to `localStorage` (see `assets/autoSave.js`). In an Android WebView
that data is wiped if the user clears app storage and is **not** included in
Android auto-backup by default.

- Migrate saves to a native-backed store (Capacitor Preferences or Filesystem), or
  at minimum mirror `localStorage` to a file on each autosave.
- Add manual export/import of a save string so players can recover.
- Enable Android Auto Backup (or Play's backup service) in the manifest and test
  restore-to-new-device.
- Write a migration path so existing browser/GitHub Pages players aren't stranded.

---

## 5. Android project configuration

- **Application ID**: choose a permanent, reverse-DNS package name (e.g.
  `com.sethrimer.theroidletd`). **This can never be changed after publishing.**
- **Version**: `versionCode` (monotonically increasing integer) and `versionName`
  (matches `package.json` version). Automate the bump in the release script.
- **SDK levels**: `minSdkVersion` 24+ is a reasonable floor; `targetSdkVersion`
  must meet Play's current requirement (Play enforces a rolling target-API
  deadline every August — confirm the current minimum at submission time).
- **Permissions**: request none unless needed. A pure offline idle game should
  ship with zero runtime permissions; remove anything Capacitor adds by default
  that you don't use.
- **Icons**: current icons under `assets/icon/` are `.ico`/`.webp`. Produce a full
  Android set — adaptive icon (foreground + background layers, 108×108 dp) and a
  512×512 PNG for the store listing.
  - Note: `electron/main.cjs:8` points at `assets/icon/Thero_icon.ico`, but the file
    on disk is `TheroMathTD_Icon.ico`. Fix that mismatch while doing icon work.
- **Splash screen**: add one so there's no white flash while the WebView boots.
- **App name**: final display name, ≤30 chars for the Play listing.

## 6. Signing and release build

- Generate an upload keystore (`keytool -genkeypair -v -keystore ... -keyalg RSA -keysize 2048 -validity 10000`).
- **Back the keystore and its passwords up offline.** Losing it without Play App
  Signing enrollment means you can never update the app.
- Enroll in **Play App Signing** (required for new apps) so Google holds the
  release key and you only hold the upload key.
- Store signing credentials outside the repo — `keystore.properties` in
  `.gitignore`, secrets in GitHub Actions if you automate.
- Build an **Android App Bundle (`.aab`)** — Play no longer accepts APKs for new apps.
- Enable R8/minification and confirm nothing in the WebView bridge is stripped.

---

## 7. Google Play Console setup

- **Developer account**: one-time $25 USD registration fee.
- **Identity verification**: Google requires legal name/address verification, and
  for personal accounts your name and address appear publicly on the listing.
  Consider whether you want an individual or organization (D-U-N-S required) account.
- **Closed testing requirement**: personal developer accounts created after
  Nov 2023 must run a closed test with **at least 12 testers opted in for 14
  continuous days** before applying for production access. Plan for this — it is
  the single biggest schedule risk. Recruit testers early.
- Release tracks to use in order: internal testing → closed testing (the 14-day
  run) → open testing (optional) → production.

---

## 8. Store listing assets

All of these must be produced:

- App name (≤30 chars), short description (≤80 chars), full description (≤4000 chars).
- App icon: 512×512 PNG, 32-bit with alpha.
- Feature graphic: 1024×500 PNG/JPG.
- Screenshots: minimum 2, up to 8, per form factor. Phone screenshots required;
  7" and 10" tablet screenshots required if you declare tablet support.
- Optional but strongly recommended: a 30s–2min YouTube promo video.
- Category (Games → Strategy or Educational), tags, contact email, and a
  **privacy policy URL** (required for all apps, even with no data collection —
  GitHub Pages can host it).

---

## 9. Policy and compliance declarations

- **Data safety form**: declare exactly what's collected/shared. If the game is
  fully offline with no analytics, this is a short "no data collected" form — but
  it must still be filled in accurately, and re-filled if you ever add analytics
  or ads.
- **Content rating questionnaire**: IARC. An abstract math tower defense should
  land at Everyone/PEGI 3.
- **Target audience & content**: if you declare children under 13 as a target
  audience (plausible for an educational math game), Families Policy and COPPA
  obligations kick in — this restricts ad networks and analytics SDKs. Decide
  deliberately.
- **Ads declaration**: yes/no.
- **Government/news/financial declarations**: all no.
- **Educational claims**: if you market it as educational, avoid unverifiable
  learning-outcome claims in the listing copy.
- **Third-party licenses**: ship an open-source-licenses screen covering MathJax,
  the fonts, and any Capacitor plugins.

---

## 10. Monetization (only if applicable)

If the game will ever charge money or sell in-game currency:

- Integrate Google Play Billing (Capacitor plugin or a native bridge). Play
  requires its billing system for in-app digital goods.
- Define products in the Console; test with license testers.
- Server-side receipt validation if purchases unlock anything meaningful.
- Restore-purchases flow.

If it ships free with no IAP and no ads, skip this section entirely — it removes
a large amount of compliance surface.

---

## 11. Pre-launch quality gates

- Run existing checks green: `npm run typecheck`, `npm run lint`, `npm test`,
  `npm run test:unit`.
- Add an Android smoke test to `docs/SMOKE_TEST.md`: install the release `.aab`
  via internal testing, complete a full campaign wave, background/foreground the
  app, force-kill and relaunch, confirm the save survived.
- Use Play Console's **pre-launch report** (automated device farm) and fix
  crashes/ANRs it surfaces.
- Test on at least: one low-end phone, one flagship phone, one tablet.
- Verify APK/AAB size — stay well under the 200 MB base module limit; check
  `assets/` (audio, sprites, fonts, vendored MathJax) for unoptimized files.

---

## 12. Suggested order of work

1. Vendor fonts + MathJax locally; tighten CSP. *(unblocks offline play)*
2. Harden save persistence and add export/import.
3. Mobile QA pass on real hardware: touch, back button, lifecycle, perf.
4. Add Capacitor, generate `android/`, wire icons/splash/manifest.
5. Create the Play developer account and start identity verification (slow).
6. Produce store listing assets and the privacy policy page.
7. Build a signed `.aab`; push to internal testing.
8. Recruit 12+ testers; start the 14-day closed test clock.
9. Complete Data Safety, content rating, and audience declarations.
10. Apply for production access; submit for review (allow days-to-weeks).
